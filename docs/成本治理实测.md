## 四、单次问答成本（可复算）

一次完整问答（`qa.plan` + `qa.answer` + `qa.check`）实测约 **¥0.028 ~ ¥0.032**：

```
qa.plan     ¥0.0090（首条流水样例）
qa.answer   ¥0.0235
qa.check    ¥0.0020 左右
```

按 ¥20/日预算，日均可跑约 **600 次问答**；按峰值单价上浮仍有余量。

## 五、成本治理机制（代码位置）

| 机制 | 位置 | 行为 |
| --- | --- | --- |
| 分档路由 | `core/llm.py::route` | `classify`/`extract` 走 flash，`reason` 走 pro |
| 日预算熔断 | `core/cost.py::CostGuard` | 超 `cost_daily_budget_cny` 停止调用云端 |
| 告警阈值 | `cost_warn_ratio`（默认 0.8） | 用到 80% 打告警 |
| 前缀缓存 | `llm_cache_enabled` | 固定 system prompt 放最前，命中价约 1/30 |
| 成本落盘 | `cost_tracker_path` | 每次调用追加 JSONL，可离线汇总 |
| 配置页可改 | `/api/v1/config` | 预算/模型/缓存开关可热改（写 `.env` + 清缓存） |

## 六、两个实测结论（对报告写作有影响）

1. **思维链计入输出**：本仓模型强制输出 reasoning，且按输出计费。
   早期 `max_tokens=500` 时推理吃满额度、`content` 为空但 HTTP 仍 200，
   等于**花了钱没拿到答案**。现规划/自检取 2500、答案取 3000，
   并给 `LLMResult` 加 `truncated` / `reasoning_tokens` 让截断可诊断。
2. **`cost_cny = 0` 不一定是没花钱**：走 cache provider 或本地模型时确实为 0；
   但若 `finish_reason=length` 被截断，也表现为"很便宜"——需结合
   `reasoning_tokens` 一起看。
