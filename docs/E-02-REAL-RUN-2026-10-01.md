## 口径补充（2026-10-01 代码修复与内存型真实 pipeline 实测；持久库对比待验）

- pipeline 已把 KEV/NVD 解析出的最近 10 个去重 CVE IDs 传给 OSV、一个传给 cve.org；scheduler 也从持久 intel.items 读取种子，并按源记录本进程已尝试项。404/无匹配记为无新文档；未发请求明确记 not_requested；fixture 降级和 OSV 部分失败单独留 user_visible fallback。
- OSV 解析器把响应 id 本身是 CVE 的情况写入 cve_ids；直接真实探测（给 CVE-2021-44228）时 OSV/cve.org 均返回非 fixture RawDoc、各解析 1 条，OSV 输出 `cve_ids=[CVE-2021-44228]`。
- 随后以 `MemoryEventStore` 做了真实联网端到端 pipeline probe（`sourceIds=[cisa_kev,osv,cve_org]`，不写 SQLite）：KEV 实抓版本 `kev_2026.09.30` 并解析 1730 条；OSV 和 cve.org 各抓取非 fixture RawDoc、各解析 1 条；OSV 的 `CVE-2026-71362`、cve.org 的 `CVE-2026-76504` 分别成功归并到对应 KEV 情报，fallback 0。正式落库/fixture 比较表仍待专用 trace 验收。
- common fetchJsonWithRetry 现在对 404 等确定性 4xx 不重试；429 尊重 Retry-After，5xx/网络错误有界退避。
- arXiv F1 已增加每进程≥3秒间隔、429/5xx 有界重试、15秒超时、成功查询缓存；ingest:once 在线模式默认最多富化 50 条，其余写入 pending 数；`npm run enrich:pending -- --limit=20` 只选尚无 enrich.items 的放行条目分批续跑（实时模式需 SAFETRACE_ENRICH_OFFLINE=false）。已存在 fixture 论文的富化记录不会自动覆盖；若要重试需后续显式参数设计。
- 诊断页面 `/ingest-diagnostics` 读 SQLite 最近 trace，展示本轮来源、无新文档、fixture/partial 降级、DQ 与富化覆盖；跨源来源条数可能重叠，不能相加当 unique CVE。SQLite events 的 seq 已改为事务内分配并加唯一索引；重复采集仍是 append-only，多轮需按 trace 查看。
