# 演示口径说明（初赛）

> 用途：**回答"这个数字是怎么来的"**。初赛评委最常问的不是"功能有几个"，
> 而是"这个结果可信吗"。本文件把每一个会出现在界面上的数字与它的来源写清楚，
> 包括**哪些还没做**。
>
> 配套：`docs/评测实测结果.md`（指标实测）、`docs/验收清单.md`（验收状态）、
> `scripts/check_db_after_ingest.py`（数据体检，可现场跑）。

## 二、富化覆盖：**94 / 1451（约 6.5%）**

| 项 | 值 | 说明 |
| --- | --- | --- |
| 已完成 7 维富化 | **94 条** | 其中真实采集 83 条、预置样本 11 条 |
| 未富化 | **1357 条** | 只有采集到的原始描述 + 来源链接 |
| 富化结论进检索空间 | **94 / 94** | 切片 `owner_type='enrichment'`，实测缺口 0 |

**为什么不全量富化**：富化逐条调用 LLM，实测**约 7 秒/条**、单条约 ¥0.01。
全量 1440 条约需 3 小时、约 ¥14（实测：94 条约 12 分钟、¥1.0）。这笔钱与时间对初赛演示的边际收益很低，
所以**按演示价值抽样**（覆盖 vLLM / Ollama / LangChain / LlamaIndex /
Transformers / HuggingFace / PyTorch / TensorFlow / MLflow / Triton 等），
其余如实标注"本条目尚未富化"（`DetailView.vue`）。

**如果被问"为什么只有这些有富化"**：上面的抽样口径就是答案 ——
不是做不到，是**按价值取舍**；补齐入口是现成的
（`POST /api/v1/enrich/backfill` 或 `python -m aiintel.cli enrich --vuln-id <id>`）。

## 三、检索质量：三个会当场暴露的问题已修

### ① 语料污染（最严重）

采集用 NVD **服务端关键词**、**子串匹配**，`rag` / `triton` / `llama` 把
非 AI 内容采了进来：**Rage** 游戏、**Ragnarok** 面板、**Triton** CMS、
Websense **TRITON**、**Quotes llama** WordPress 插件、**Triton** Minecraft 插件。

**实测后果**：查 `ollama DNS rebinding` 把 **Windows XP 的 DNSAPI 漏洞排在第一位**。

**修法**：词元级相关性判定（`services/ingest/relevance.py`）——
弱标识（`triton`/`rag`/`llama`）**单独出现不采信**，必须与强标识共现。
于是 **Triton Inference Server 保留**、**Minecraft Triton 排除**。
清除 258 条脏数据（`scripts/purge_non_ai.py`），并在检索路径加第二道过滤。

### ② 语义检索曾静默失效

保护逻辑写成了"语料超 500 条就不做语义召回"，语料涨到 8 万切片后
**语义检索整个被关掉**、退回纯关键词。已改为"先关键词召回、再在候选内语义重排"。

### ③ 慢查 10 秒

组合键被拆成两个 `in_()` 导致笛卡尔放宽；且候选按**切片**展开（一个漏洞几十个切片）。
已改为组合键匹配 + 每个 owner 只取代表切片。

| 查询 | 修前 | 修后 |
| --- | --- | --- |
| ollama DNS rebinding | 10.3s | **0.43s** |
| vLLM 远程代码执行 | 8.5s | **0.20s** |

## 四、语义检索：真的在跑，且有边界

| 项 | 值 |
| --- | --- |
| 运行时 | ONNX Runtime（依赖约 15MB，**不需要 torch**） |
| 权重来源 | `hf-mirror.com`（本机 `huggingface.co` 不可达） |
| 模型 | `paraphrase-multilingual-MiniLM-L12-v2` 量化版（384 维） |
| 模型选型依据 | 中文版 `bge-small-zh` 把 `vLLM`/`LangChain`/`CVE-…` **5/5 全切成 `[UNK]`**；多语言版 **0/5** |

**能力边界（主动说明，不等被问）**：
- 语义重排发生在**关键词候选集内**，不是全库向量检索；
- 宿主机 PostgreSQL 16.15 **无 `vector` 扩展**，所以走内存余弦；
  **compose 的 `pgvector/pgvector:pg16` 自带 `vector 0.8.6`**，那边可用向量列。
