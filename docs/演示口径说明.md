> 用途：**回答"这个数字是怎么来的"**。初赛评委最常问的不是"功能有几个"，
> 而是"这个结果可信吗"。本文件把每一个会出现在界面上的数字与它的来源写清楚，
> 包括**哪些还没做**。
>
> 配套：`docs/评测实测结果.md`（指标实测）、`docs/验收清单.md`（验收状态）、
> `scripts/check_db_after_ingest.py`（数据体检，可现场跑）。

## 一、库里的数据从哪来

> **具体条数见 `docs/FACTS.md`**（由 `python -m scripts.gen_facts` 实时生成）。
> 本节只讲**判据**，不写数字 —— 数字写两遍必然漂移（本文档就漂过一次）。

| 分类 | 判据 | 来源 |
| --- | --- | --- |
| **真实采集** | `raw_item` 里有同 `external_id` | NVD API 真实拉取，再经 AI 相关性清理 |
| **演示预置** | 无 `raw_item` 支撑 | `scripts/demo_seed.py` 写入的样本（`CVE-2026-3xxxx`） |

**判据说明**：**不能**用 `cve_id like 'CVE-2026-%'` 判断"这是合成数据"——
真实 NVD 数据里也有大量 2026 年 CVE（实测 774 条中 763 条是真实采集的，**历史值**）。
唯一可靠判据是**证据链**。

现场可自查（只读，可当场跑给评委看）：


## 二、富化覆盖（数字见 `docs/FACTS.md`）

| 项 | 说明 |
| --- | --- |
| 已完成 7 维富化 | 其中大部分是真实采集，其余是演示预置样本 |
| 未富化 | 只有采集到的原始描述 + 来源链接，**界面会如实标注** |
| 富化结论进检索空间 | 切片 `owner_type='enrichment'`；**缺口必须为 0**（`docs/FACTS.md` 有此项） |

**覆盖率的准确值、实时值见 `docs/FACTS.md`。**

**为什么不全量富化**：富化逐条调用 LLM，实测**约 7 秒/条**、单条约 ¥0.01。
全量约需 3 小时、约 ¥14；实测 94 条约 12 分钟、¥1.0。这笔钱与时间对初赛演示的边际收益很低，
所以**按演示价值抽样**（覆盖 vLLM / Ollama / LangChain / LlamaIndex /
Transformers / HuggingFace / PyTorch / TensorFlow / MLflow / Triton 等），
其余如实标注"本条目尚未富化"（`DetailView.vue`）。

**如果被问"为什么只有这些有富化"**：上面的抽样口径就是答案 ——
不是做不到，是**按价值取舍**；补齐入口是现成的
（`POST /api/v1/enrich/backfill` 或 `python -m aiintel.cli enrich --vuln-id <id>`）。

### 富化结论**确实**被问答引用（可现场验证）

```bash
python -m scripts.verify_enrichment_used
```

实测问 `CVE-2026-102697 怎么修复？`：

```
命中 8 条  →  {'vuln': 1, 'enrichment': 7}
引用 S1 vuln:CVE-2026-102697          ← 该 CVE 自己的切片
     S2 enrichment:CVE-2026-102697    ← 该 CVE 的富化结论
```

此前这条链路是**断的**（三个叠加缺陷：`index_owner` 逐次"先删后写"导致 7 维只活 1 维；
富化文本不含 CVE 编号导致按编号检不到；弱词淹没精确词）。已全部修复。

### ⚠️ `fix` 维度是**规则版**：通用建议重复是**声明过的行为**

实测 57 条漏洞共用同一条 `immediate`（"按影响面收敛对外暴露…"）。
这**不是数据串了**，是 `fix.py` 的设计：**升级版本号取自公告原文（确定性），
通用缓解建议是模板**，并在 `value.mock=true` 与 `degraded_reason` 里显式声明：

> "F5 本轮为规则实现：版本号取自公告原文，通用建议为模板（未接 LLM 组织与正文抓取）"

**被问到时照实说**：版本号可信（来自公告原文），通用建议是规则模板；
`cvss` 的 `base_score` 由向量本地计算，分布正常（7.5 / 8.8 / 7.8 / 7.1 / 9.8 …）。

## 三、检索质量：三个会当场暴露的问题已修

### ① 语料污染（最严重）

采集用 NVD **服务端关键词**、**子串匹配**，`rag` / `triton` / `llama` 把
非 AI 内容采了进来：**Rage** 游戏、**Ragnarok** 面板、**Triton** CMS、
Websense **TRITON**、**Quotes llama** WordPress 插件、**Triton** Minecraft 插件。

**实测后果**：查 `ollama DNS rebinding` 把 **Windows XP 的 DNSAPI 漏洞排在第一位**。

**修法**：词元级相关性判定（`services/ingest/relevance.py`）——
弱标识（`triton`/`rag`/`llama`）**单独出现不采信**，必须与强标识共现。
于是 **Triton Inference Server 保留**、**Minecraft Triton 排除**。
清除 258 条脏数据（`scripts/purge_non_ai.py`），并在检索路径加第二道过滤。

### ② 语义检索曾静默失效

保护逻辑写成了"语料超 500 条就不做语义召回"，语料涨到 8 万切片后
**语义检索整个被关掉**、退回纯关键词。已改为"先关键词召回、再在候选内语义重排"。

### ③ 慢查 10 秒

组合键被拆成两个 `in_()` 导致笛卡尔放宽；且候选按**切片**展开（一个漏洞几十个切片）。
已改为组合键匹配 + 每个 owner 只取代表切片。

| 查询 | 修前 | 修后 |
| --- | --- | --- |
| ollama DNS rebinding | 10.3s | **0.43s** |
| vLLM 远程代码执行 | 8.5s | **0.20s** |

## 四、语义检索：真的在跑，且有边界

| 项 | 值 |
| --- | --- |
| 运行时 | ONNX Runtime（依赖约 15MB，**不需要 torch**） |
| 权重来源 | `hf-mirror.com`（本机 `huggingface.co` 不可达） |
| 模型 | `paraphrase-multilingual-MiniLM-L12-v2` 量化版（384 维） |
| 模型选型依据 | 中文版 `bge-small-zh` 把 `vLLM`/`LangChain`/`CVE-…` **5/5 全切成 `[UNK]`**；多语言版 **0/5** |

**能力边界（主动说明，不等被问）**：
- 语义重排发生在**关键词候选集内**，不是全库向量检索；
- 宿主机 PostgreSQL 16.15 **无 `vector` 扩展**，所以走内存余弦；
  **compose 的 `pgvector/pgvector:pg16` 自带 `vector 0.8.6`**，那边可用向量列。

## 六、现场演示建议顺序

1. **问答**：问 `vLLM 有哪些远程代码执行漏洞？` —— 前几条都是 7 维富化，面板有内容；
2. **点开引用**：`/vulns/<cve>/evidence` 看证据链（富化字段 + 来源片段 + 关系子图）；
3. **主动说覆盖**：先打开 `docs/FACTS.md` 念当前覆盖率 —— **先说，不等问**；
4. **跑一次数据体检**：`python -m scripts.check_db_after_ingest` —— 证明数字可复现；
5. **如被问"怎么保证不是编的"**：`docs/评测实测结果.md` +
   `eval/datasets/MANIFEST.md`（标注集里 60 条 `needs_human` 也是如实登记的）。
