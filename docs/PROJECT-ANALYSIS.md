## 1. 一句话说清：SafeTrace 是什么

**一个"能自己查资料的漏洞情报问答系统"。**

安全工程师在对话框里打一句话——"Ollama 那个未授权访问漏洞影响我们哪些服务？今晚先修哪个？"——系统自己决定去查漏洞库还是翻文档，几秒后给出一个**带出处、带推理链、带修复优先级**的答案。

它参加的是「中国电子杯」大赛赛题九《智能体驱动的 AI 安全知识情报系统》，作品截止 2026-10-19。

| | 人工 | SafeTrace |

## 3. 系统怎么跑的（把流水线当成快递分拣）

```
7 类情报源  →  Y 监测线  →  情报对象  →  F 富化线  →  知识底座  →  Q 问答线  →  网页
（收件）      （分拣）      （贴单）      （加工）      （上架）      （查件）     （取件）
```

| 步骤 | 干什么 | 代码在哪 |
|---|---|---|
| **① 收件** | 从 CISA KEV、NVD、OSV、cve.org、Ubuntu USN 等源抓数据（7 类登记、5 个连接器在跑） | `src/ingest` |
| **② 分拣** | 统一格式 → 去重归并（同一个漏洞四套编号合成一条）→ **DQ1 质量闸门**打分，脏货进隔离区 | `src/ingest` |
| **③ 贴单** | 生成不可变的 `IntelItem`（情报对象），带上来源和哈希 | `contracts/schemas` |
| **④ 加工** | 富化：关联论文、补 CVSS/EPSS 评分、给修复建议、校验冲突、评估本地资产影响 | `src/enrich` |
| **⑤ 上架** | 切块 → BGE-M3 向量化 → 存进 Qdrant，可语义检索（默认 BM25，dense 需起本地栈） | Qdrant + `src/qa` |
| **⑥ 查件** | 理解问题 → 混合检索 → 合成四段式答案，每条结论都带引用 | `src/qa` |
| **⑦ 取件** | 网页：态势大屏、情报列表、问答页、资产监控等页面 | `web/` |

**另外还有一条"本地资产线"（A 线）**：扫描本机 git 仓库/项目目录的依赖清单，生成技术栈快照，
再和情报做确定性版本匹配——所以问答不只是分析问题，还能结合**你自己的仓库**给出三个方向的解决方案。

**2026-10-11 内部 Agent 时效增量**：新入口把“源完成→持久交接→快速CVSS/EPSS→验证索引准备”接通，原始来源先可问答，不等慢富化。timely档NVD30分钟、KEV15分钟，仍遵守官方限流；旧结果受事件版本与token检查，失败/停机有持久续接。全量909/909及受控集成测试通过，**没有因此证明实源6h SLA或72h生产运行**。操作与边界见 [教程§7](TUTORIAL.md#7-时效与指标口径评分类指标唯一口径)。

**四根"承重墙"**，不属于某一条线但每条线都靠它：

- **MG1 模型网关**（`src/gateway`）：所有模型调用的唯一出口。换本地/云端模型只改配置、不改代码；还管限流、熔断、降级、计量。
- **自研 TaskGraph 编排**（`src/qa/src/orchestrator`）：把"监测/富化/问答/自愈"当成四个 Agent 编排起来，支持挂起-恢复。
- **兜底阶梯**（`src/qa/src/ladder`）：工具 → 规则 → 本地 Jev → 云 LLM → 人工。任何一层拿不准就**明说**，不硬编。
- **Lineage 溯源账**（`src/shared`）：`trace_id` 从采集贯穿到答案，每步记输入输出哈希，可查"这个数字从哪来"。

## 4. 三个关键设计（评委最可能追问）

**① 为什么所有模型调用都必须走 MG1 网关？**
大赛宣讲会的明确红线：接口要标准化、与系统解耦、能灵活切换本地或云端模型。所以代码里禁止 `import` 任何模型厂商 SDK，切换只改 `config/models.yml` 一行。

**② 为什么判断类任务不交给大模型？**
大模型会"编"。所以路由、分级、证据充分性这类**结构化判断**交给 Jev（只能从给定选项里选的决策模型，输出受 schema 约束，不会幻觉）；大模型只负责最后"说人话"。Jev 是闭源服务，已设计同构降级。

**③ 为什么脏数据要单独隔离？**
情报源天然脏：网页说改版就改版、同一漏洞四套编号、时间戳时区混乱、POC 链接失效、CVE 有 REJECT/RESERVED 状态。**宁可少一条，不可错一条**——错一条会污染整个知识库。

**④（加分项）为什么问答能给出"解决方案"却不会瞎编？**
因为方案只从两类硬事实里长出来：本地扫描出的依赖清单（`var/assets.sqlite`）和已发布情报里的版本规则。
升级目标版本必须取自 Ubuntu USN / CISA KEV 公告原文，本系统不做跨生态包名映射；范围约束下界、同名跨生态、扫描降级都会显式提示"无法判定"。
**unknown 不等于安全**——这条贯穿整个项目。

## 6. 我的判断：三个真问题 + 五个建议

### 真问题
1. **"跑通"和"做好"之间有道坎。** 链路能跑不等于答得准。目前没有任何公开的准确率数字——论文关联 recall@5 是零基线，评委一句"换个新 CVE 试试"就可能露怯。
2. **默认配置太"离线"。** 演示时默认 `cache` provider 是确定性占位，没有真实 LLM 推理；语义检索也退回 BM25。亮点功能都需要额外配置才能看到。
3. **富化是明显的短板。** 赛题三大项里"情报富化"占 15 分，而覆盖率不到 30%、多个维度靠 fixture 顶，这是最容易被攻的点。

### 建议（按投入产出排序）
| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **P0** | 用 20 条真 CVE 录一版**不靠 fixture** 的端到端演示 | 唯一能挡住"跑个新数据看看"的东西 |
| **P0** | 富化挑 1 个维度做实（推荐 F4 CVSS + EPSS），拿出覆盖率数字 | 比六个维度都半吊子得分高 |
| **P1** | 建 20 条标注集，报出 recall@5 / 准确率 | 没数字就没法证明"做得好" |
| **P1** | 补 72h 挂机端到端实测 + 自愈演练录像 | 禁砍项，现在只有代码没有证据 |
| **P2** | 前端演示动线打磨（问答 → 证据 → 推理链一屏看完） | 演示效果分，性价比高 |

## 7. 附：初学者怎么上手这个项目

```bash
git clone https://github.com/Niangaol/safetrace.git && cd safetrace
git config core.hooksPath .githooks   # 每次 clone 后都要
npm ci && npm ci --prefix web         # Node >= 24，只需一次

npm run check      # 门禁：typecheck + 全量单测 + 契约校验 + 前端构建
npm run smoke      # 端到端冒烟：fixture 回放跑完整链路
npm run demo:serve # 窗口 A：本机 API :8000（启动即实跑采集→DQ1→富化）
npm run dev --prefix web   # 窗口 B：前端 :5173
```

**读代码的顺序**（从入口往里看，别一上来扎进细节）：

1. [`README.md`](../README.md) §1 — 项目现状总表，最快建立全局观
2. [`TUTORIAL.md`](TUTORIAL.md) §5 — 每条线怎么用、有哪些命令
3. `contracts/schemas/*.json` — 8 个接口契约，**系统的"法律"**，先看这个再看代码会省很多时间
4. `src/ingest/src/pipeline.ts` — 数据从进来到出去的完整旅程，最好的入口文件
5. `src/qa/src/q4-answer.ts` — 答案是怎么合成出来的
6. `src/qa/src/solution-plan.ts` — 三个方向的解决方案是怎么从本地快照长出来的

**几条能少踩坑的经验**（来自仓库自己的记录）：
- 契约 2026-10-03 已冻结，之后只能加字段、不能改语义——动 `contracts/` 前先看 `CHANGELOG.md`
- 前端默认只请求真实后端，拿不到就报错，**不会静默回退假数据**；要看静态演示得显式设 `VITE_DEMO_MODE=true`
- esbuild 在系统 TEMP 建临时文件会被拒，先 `mkdir -p .tmp` 再把 `TEMP/TMP` 指过去
- 别把 `event` 数量当成唯一漏洞数——事件库是 append-only，同一漏洞会被多源重复记录
- 环境坑与排障清单见 [TUTORIAL.md](TUTORIAL.md) §1.2 与 §11
