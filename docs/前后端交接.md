## 1. 后端目前必须对前端保证的契约

### 1.1 `/qa/chat`（SSE 流式）

前端 `QaView.vue` 消费的事件与字段（`web/src/api.ts` 解析）：

| 事件 | 前端消费点 |
| --- | --- |
| `status`/阶段事件 | 流水线步骤渲染 |
| `trace` | 检索过程可视化 |
| `citation` | 证据卡片：**必须有 `trust`、`published_at`**（未评估=null 如实标） |
| `token` | Token 成本显示 |
| `done` | 答案落盘 + 元信息面板 |

`done` 帧字段（**缺一不可，缺了前端面板缺行**）：

- `degraded` / `degraded_reason`：降级必须显式（三条工程红线之一）。
- `llm_degraded`、`elapsed_ms`、`model`、`cost_cny`、`citation_count`、`reasoning`。
- **C-04**：`stale_warning`（null 是唯一可免提示情形；有值必须展示时效风险）。
- **A-04**：`injection_guard`：
  - `screened` = **“做过筛查”**，检出危险也是 `true`；仅**无引用时为 `false`**。
  - `max_score` / `flags[]` 是**实际字段**（不是保留位）。前端有 flags 即红字告警 + 徽标。

请求体：前端 `stores/qa.ts` 的 `ask()` 现在**必带 `data_domain`**（`public|private`，
默认 `public`，与后端一致）。前端「公开域/私有域」切换只发值、不做安全承诺；
**私有域策略拒绝走 4xx 业务错误如实上屏，永不 mock**（C-05/A-03 隔离由后端强制）。

### 1.2 mock 纪律（三方红线，DeepSeek 改后端时别碰这三条）

1. 先真后假（在线失败才回退预置数据），回退必须伴随全站横幅 + 原因；
2. `VITE_USE_MOCK=false` / `never` 模式**绝不回退**；
3. **4xx 业务错误永不 mock**（包括 C-05 私有域 422 策略拒绝）——mock 层只认
   「网络/5xx」一类失败。`scripts/smoke-data-source.mjs` 6/6 守这条。

前端新增了对 `qa.answers` 两字段（stale_warning / injection_guard）的解析，
mock 层（`web/src/mock.ts`）与演示样本（`web/src/qaSample.ts`）已对齐上述语义。
